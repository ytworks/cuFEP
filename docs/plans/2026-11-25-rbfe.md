# 相対結合自由エネルギー(RBFE)の製品 `cufep rbfe`
Status: In progress (branch `feat/rbfe`)
Refs: `docs/plans/2026-11-18-abfe-engine.md`; OpenFE `RelativeHybridTopologyProtocol`(main, v1.13); Midgley et al. JCIM 2025, 65, 512; Xu JCIM 2019, 59, 4720; Ross et al. Commun Chem 2023

## Context
- オーナーの指示(2026-11-25): 今の機能とコードをできるだけ共通化して RBFE(相対 FEP)を作る。YAML は別フォーマットでよい。
  example は TYK2 と A2A の 3 化合物ずつで、ddG と DG を出す。既定値と実行時間は OpenFE・FEP+ と同じにして、
  精度はできるだけ高くする。cuPotential を既定にする。膜タンパク質は膜付きで計算する。
- オーナーの回答: DG の基準は「実験値」と「ABFE」の両方を実装し、既定は実験値。置き場所は同じリポジトリ・同じ image の
  `cufep rbfe`(`src/cufep/rbfe/`)。

## 既定値(全部 YAML で変えられる。根拠は新しい `docs/rbfe.md` に引用する。docs では製品名でなく論文を引く)
| 項目 | 既定 | 根拠 |
|---|---|---|
| トポロジー | hybrid(core は single、unique 原子は dual)、lambda の関数も同じ: core は線形、unique の電荷は前半で消して後半で入れ、LJ は前半で入れて後半で消す | OpenFE(perses の HybridTopologyFactory) |
| soft-core | Gapsys 型の LJ、α 0.85、電荷の soft-core なし。core–unique の exception は切る | OpenFE |
| 原子の対応 | Kartograf(0.95 Å、H は H にだけ、環は完全一致だけ)。拘束の長さが変わる対応は外す | OpenFE の既定 |
| ネットワーク | YAML の `edges`。無ければ LOMAP network(全化合物が cycle に入る) | OpenFE の業界ベンチマーク |
| 窓 | ALS: 9 窓から、閾値 0.04、候補 101、溶媒中のリガンドで 50 ps。その窓を両レグに使う | Midgley 2025(RBFE のための方法) |
| 長さ | production 5 ns、equilibration 1 ns(窓ごと) | FEP+ の既定 5 ns、OpenFE 5 + 1 ns |
| MD・系 | 4 fs、HMR 3 amu、cutoff 0.9 nm、余白は complex 1.0 nm・solvent 1.5 nm、ff14SB、OpenFF 2.2.1 AM1-BCC、TIP3P | OpenFE と同じ。ABFE と共有 |
| REST2 | on。設定は ABFE と共有(ハイブリッドリガンド + pocket) | FEP+ は RBFE で REST2 を使う |
| 膜 | `membrane.enabled` で complex レグを POPC 二重層(Lipid21)に入れる。溶媒レグは水 | ABFE と共有 |
| ddG | ΔG_complex − ΔG_solvent(MBAR)。SE は 2 レグの SE の二乗和の平方根。cycle closure は数値だけ出す | |
| DG | MLE(Xu 2019、cinnabar)。基準 `experiment`: 実験値のある化合物の平均に合わせる。`abfe`: 参照化合物を cuFEP ABFE で計算する | FEP+ 公開ベンチマーク、OpenFE 論文 |
| その他 | repeats 1、cuPotential(失敗したレグは stock OpenMM)、中性のリガンドだけ(電荷が変わる edge は書く前に拒否) | cuFEP の規則 |

計算量: 1 エッジ ≒ 2 レグ × 約 10 窓 × 6 ns ≒ 120 ns。OpenFE の 1 repeat、FEP+ の既定(2 × 12 × 5 ns)と同じ量で、
ABFE の 1 化合物(約 50 窓)の約半分。全エッジの全レグを今のスケジューラと MPS で 8 GPU に配る。
目標: 3 エッジの部分は、同じ image・8 GPU の ABFE example 1 本の 1.5 倍以内。時間はチャットでだけ報告する(ライセンス)。

## 共通化(ABFE の結果は 1 ビットも変えない)
- そのまま使う: backends、HREX、storage、scheduler、MPS、pre-equilibration、ALS の規則、MBAR と判定、タンパク質・膜・溶媒和の準備、
  ligand の電荷、stats。
- 一般化する: 状態(`AlchemicalState` → 経路の関数。ABFE の restrain/discharge/vanish はその一つ)、`StateEnergyEvaluator`
  (力のグループごとに「λ の 2 次式」「線形」「値ごとに評価」を宣言する)、ALS の stage 名、tail correction を両端に、
  `run_leg` を共通部分と ABFE だけの拘束に分ける、ジョブを「レグ」一般にする。
- プラグインに載せるのは電荷の offset だけにする(core、delete、insert の 3 つと REST2)。リガンドの LJ は ABFE と同じく
  stock カーネルの soft-core 力、リガンド内の対は CustomBondForce に置く。プラグインで sigma の offset は未確認だから。
- 新規 `src/cufep/rbfe/`: 設定、原子の対応、ネットワーク、hybrid の System、エッジの準備、ddG・cycle closure・MLE・DG、CLI
  (`cufep rbfe plan|run|analyze`)。依存に kartograf、lomap2、cinnabar を足す。

## 検証
- CPU: hybrid の λ=0 と λ=1 のエネルギーが A と B の System(+ dummy の結合項)に一致すること。evaluator が各状態を
  設定した値に一致すること。同じ分子の edge(A→A)の ddG が 0 になること。MLE と cinnabar が合成データで一致すること。
  書く前の拒否。`run` と `analyze` で同じディレクトリの状態になること。各書き込み段階での中断と再開。ABFE の既存テスト全部。
- GPU: hybrid の各状態で両バックエンドが合うこと。REST2 付き hybrid の状態エネルギー。

## 記録

### 2026-11-25 手順 2: hybrid の電荷をプラグインに載せる(`spikes/m36_hybrid_charges_on_the_backends.py`)
- TYK2 の複合体(ejm_31、34,078 原子 + 新しい粒子 5)で、core 27、消える原子 5、現れる原子 5、REST2 の側鎖 137 原子。
  global parameter 5 つ(core・delete・insert の電荷、rest2_dq、rest2_ds)、core 原子は電荷の offset を 2 つ持つ。
  プラグインはこの力を受け付けた。
- 11 x 2 状態(x = 0〜1、s = 1 と 0.6)の状態 x = 0, s = 1 からの差: 電荷を直接書いた System(stock、倍精度、
  Ewald 1e-6)に対してプラグインは最大 0.037 kT(GPU テストの水準 0.1 kT)、stock を同じ Ewald 許容 5e-4 で動かすと
  0.037 kT。λ の前半と後半それぞれで 3 点から求めた 2 次式の誤差は最大 7e-5 kT。
- stock の offset 版と直接書いた版の絶対値は、s = 0.6 で 3.50 kT ずれ、分散補正を切ると 1e-3 kT になった。stock OpenMM は
  epsilon の offset が変わっても分散補正を更新しない。プラグインは直接書いた System と同じ値を出す。PROGRESS の未解決
  項目「REST2 で両バックエンドの分散補正が違う」は、stock の側が違うことがこれで分かった(ABFE も同じ)。
- プラグインの積分器と barostat で x = 0.25, s = 0.6 の MD 2500 ステップ(リガンドの LJ を別の力に入れて): 安定、体積が動く。
  最初の版はリガンドの LJ を外していたため、電荷を持つ原子が水に寄って発散した(spike の作りの問題)。
- 実行中の Context と新しい Context: 絶対値は 0.6 kT ずれるが状態間の差は 0.02 kT 以内で一致(-421.632 と -421.623 kT)。
- 結論: 設計どおり、プラグインには電荷の offset だけを載せる。

### 2026-11-25 手順 3〜6: 実装
- 共通部分: 状態の型の振り分け(`state_from_dict`、`make_state_evaluator`、stage `morph`)、replica exchange を
  `workflow.sample_leg` に切り出し、ABFE の run を `prepare_run`/`execute_jobs`/`finish_run` に分割(ABFE の参照計算を
  同じスケジューラで流すため)、ジョブが自分の実行関数を持てるスケジューラ。ABFE の単体テストはこの後も全部通る。
- `src/cufep/rbfe/`: hybrid(OpenFE の規則、プラグインには電荷だけ)、状態と評価(半分ごとの 2 次式)、原子の対応
  (Kartograf と OpenFE の拘束の規則)、ネットワーク(cinnabar の MLE、実験値または ABFE の基準、cycle closure)、
  設定(別フォーマット)、エッジの準備(膜では B を A と同じ剛体運動で動かす)、レグ、ドライバ、CLI `cufep rbfe`。
- 計画から変えた点: tail correction は RBFE では入れない(OpenFE の相対計算の既定 `use_dispersion_correction: False`)。
  両端に入れるには標本の保存形式と解析の推定量を変える必要があり、ABFE と共有する中核に手が入るため。
- 依存: kartograf 2.0.0、lomap2 3.3.0、cinnabar 0.6.1(OpenFE 1.13 と同じ版)を `docker/environment-rbfe.yml` で
  `--freeze-installed` により追加。既存のパッケージは 1 つも変わらない(dry run で確認)。
- テスト: CPU(hybrid の両端が A・B の System と一致、評価が各状態の直接計算と一致、E(x)=E(1-x)、ネットワークが
  cinnabar と一致、設定、エッジの準備から ddG まで adaptive と fixed)、GPU(hybrid の各状態で両バックエンドが
  厳しい Ewald 和と一致、REST2 付きの評価、HREX)。
- example: TYK2 ejm_31、ejm_46、ejm_49 の LOMAP score は 0.37、0.27、0.04(3 本目は置換基の入れ替えで unique 8+11 原子。
  TYK2 の ejm_31 の隣接化合物はどれも共通骨格 28 原子だけが対応し、score はおおむね 0.04〜0.37)。承認どおり進める。
  A2A 4e、4b、4o は 0.82〜0.90。

### 2026-11-25 オーナーの指示による変更
- 「ABFE は不要」「RBFE だけで DG を出す方法をちゃんと実現せよ」: DG の基準に ABFE を使う機能(`dg.references: abfe`)を
  削除した。DG は edge だけからの MLE で、基準は実験値の平均、実験値が無ければネットワークの平均。ABFE を持ち込んだのは
  計画の質問で私が選択肢に加えたためで、依頼には無かった。example の DG もこの方法で出す。
- GPU の並列化に直列の区間を作らない: complex レグが溶媒レグの窓を 1 GPU で順に回っていた walk をやめ、自分で窓を選ばない
  レグの窓はすべて前平衡化の最後の構造から始める(OpenFE の始め方)。HREX の equilibration で全窓が同時に緩和する。
- 1 回目の TYK2 の実行(e4f1079)は complex レグが iteration 0 で発散して止めた: 全窓を λ=0 の前平衡化の構造からそのまま
  始めたため、λ=0 で相互作用しない B の unique 原子に水が重なった窓で発散した(プラグインでは kernel の launch failure が
  MPS を通じて同じ GPU の溶媒レグの worker も止めた)。各窓を自分の状態で最小化(OpenFE と同じ 5000 ステップ)し 10 ps の MD
  をしてから始めるよう直した。全窓を worker pool で同時に行う。回帰テストは修正前のコードで NaN になることを確認した。
